# Security policy

These are educational examples, not production-verified integrations. No supported release versions or guaranteed response times are offered yet.

Use GitHub's private vulnerability reporting if available under Security. Otherwise open an issue asking for a private contact route without disclosing vulnerability details. Never include credentials, tokens or customer data in public reports.

Use synthetic accounts. Do not disable TLS validation or token verification to make a demonstration work. Revoke any accidentally published credentials; removing a file does not remove Git history.
